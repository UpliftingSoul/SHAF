# SHAF 部署与使用手册编写规划

## 1. 目标与依据

以当前源码、锁文件和已确认的部署选择为依据，提供初次部署、日常运维、功能验收三个独立入口。旧参考材料只读且不入 Git；历史 spec/plan 仅用于定位背景。所有真实服务部署在 Ubuntu，Windows 只开发或远程操作。

## 2. 确定方案

- 单台 x86_64 Ubuntu，8 核、16GB 内存、80GB 系统盘 + 100GB 数据盘；这是低并发起步配置，训练与大型评估串行安排，不承诺压测容量。
- Vue/Nginx、FastAPI、MySQL、物流 MCP、售后 MCP、ONNX 分类器各自运行；Milvus Standalone 使用 etcd、MinIO 配套容器。
- Langfuse Cloud；聊天采用官方 DeepSeek API，嵌入/重排保留独立云 API。Qwen 为配置替换方向，不默认混用厂商参数。
- 保留分类器全参训练，提供 LoRA 模式和 CPU 依赖；合并模型后沿用评测、ONNX 导出与旁路归类。
- 个人学习/展示为目标：标准 Nginx 提供页面和 API 转发，1Panel 管理容器、文件、日志与计划任务；不安装 OpenResty，不使用面板网站/运行环境部署本项目。
- 主入口绑定服务器回环地址，以笔记本 SSH 隧道访问；可选公网 IP + 8080，并在云安全组/防火墙只允许本人或展示对象的 IP。域名、HTTPS、高并发与高可用不列为本阶段必做。

## 4. 核对与实现顺序

1. 阅读实际启动、配置、API、作业注册、SQL、知识双写和分类器文件，记录硬编码地址与不可在容器内使用的旧入口。
2. 核对 Docker、Milvus、Langfuse、模型厂商官方文档；存储服务使用显式镜像 tag，应用依赖按锁文件，验收后记录实际镜像标识，不在运行命令中自动升级依赖。
3. 完成独立生产 Compose、配置模板和 CPU 训练镜像阶段；MCP 使用容器可达监听地址。保持业务数据库、图与检索架构。
4. 写部署手册，再分别写运维、页面测试和迁移备用规划；每项操作标出执行位置、依赖和验收结果。
5. 校验 YAML、锁文件、配置引用、文档链接、文件覆盖和代码差异；执行相关受控测试。当前无 Docker 和真实云服务，明确保留 Ubuntu 镜像构建、数据库初始化、Milvus/模型/云 trace 的实际验收项。
6. 按阶段提交并推送，旧参考和真实密钥不进入版本库。

## 5. 关键约束

初始化 SQL 仅对空 MySQL 数据目录自动执行；已有库升级不重放整套 SQL。网页任务不获得 Docker socket；独立分类器的容器启停、旧 Docker 命令和破坏性知识重置由负责人操作。后台训练依赖由 CPU 镜像提供，不在服务运行时临时安装。

定时脚本在源码中仅有示例，不等同于已安装调度器；手册以手动跑通为先，按需使用 1Panel 计划任务。报告文件可能是仓库已有结果，必须查看运行时间、配置和本次作业日志后再判断实际部署通过。

## 6. 个人使用与 1Panel 修订方案

1. 部署主线缩短为准备服务器/面板 → 源码与配置 → 一次性构建 → 原路径接入 Compose → SSH 浏览器访问 → 网页初始化与验收。
2. 保留项目服务、数据库初始化与模型依赖；增加前端监听地址配置，默认仍为回环，公网 IP 模式只改环境配置。后端业务、Vue 页面与训练链路不改。
3. 1Panel V2 官方文档与 v2.3.2 源码确认：路径接入不搬移项目，导入会读取并写回同目录 .env；先拉镜像再启动，因此先构建本地镜像且不勾强制拉取。GUI 未提供 classifier profile 选择，保留显式启动命令。
4. 日常状态、日志、文件、MySQL 容器终端和计划任务转为面板入口。飞轮/模型更新保留必要命令；一致备份采用先停服务再归档，不用网站备份冒充完整项目备份。
5. 完整测试指南保留模块覆盖，仅同步执行位置。云迁移规划与架构/README 同步，不加入网站代理层。执行文档链接、命令语法、Compose 静态合同、架构覆盖和只读参考完整性检查；不声称完成真实 1Panel/Ubuntu 上机验收。
6. 用户补充：正式上线的域名、HTTPS、访问认证和长期运维保留为选读，不作为个人部署的前置。源码核对发现 HTTP 公网首次聊天依赖 secure-context randomUUID；在既有 useChat 中补同格式随机 UUID 兼容路径，保留 localStorage/业务语义，并验证新访客和已有身份。

## 10. 数据盘方案调整

- 用户确认加购 100GB 数据盘：系统、面板及 Docker 默认存储留 80GB 系统盘，项目和持久数据放 `/mnt/shaf-data/SHAF`；不修改业务代码或 Compose 相对挂载。
- 开机后核对实际空盘、SSD/云盘性能、文件系统和虚拟机指令集；只对确认的空数据盘初始化，使用 UUID 开机挂载，启动项目前重启验证。
- 用 Docker systemd drop-in 配置 RequiresMountsFor 与 AssertPathIsMountPoint；数据盘失败时系统可供 SSH 排查，Docker 不启动空目录数据库。此配置影响整机 Docker，首次部署前完成。
